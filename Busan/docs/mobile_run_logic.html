THE BOUNDARY · 唯一分界

手机自己说了算

每次启动与点「重试」都重新判定，同一个 APK 在飞机上、在没给网络权限、在连不上互联网时都会自动落到包内数据。

① 系统是否允许访问网络ConnectivityManager 取当前网络；无 INTERNET 能力 = 不允许 → 直接离线，不发任何请求。
② 手机是否真的联通互联网还要求 NET_CAPABILITY_VALIDATED（系统实测可上网）；连着 Wi-Fi 但打不开网页也判离线。

联网分支

联网 · 云端库

不经过本电脑

1
判定通过，进入云模式

BusanHost.netAllowed() 返回 true → cloud.js 依次请求云端库。

2
读云端数据库

GitHub raw 上的 mobile/cloud/spots.json（三语档案 + 坐标 + 官网 mId），12 s 超时。

3
抓景点官方网站

沙下区 saha.go.kr/tour/contents.do?mId=…、甘川 gamcheon.or.kr；Accept-Language: ko-KR，saha 带 Referer，抽 id="conts" 正文前 12 行。

4
同一套资料组装

按意图取字段（交通 / 门票 / 开放时间 / 拍照点 / 概览），正文压到 3–5 条；只输入景点名走精简版。

5
官网核对区

显示官网原文（韩文）、抓取时间、官网链接；抓不到就标「未取到正文」，不假装读过。

离线分支

离线 · 包内数据

同一引擎，不降级版式

1
① 不允许联网

netAllowed=false → reason="blocked"，不发请求，直接读包内快照。

2
② 允许但取不到云端库

两个 endpoint 全失败 → reason="cloudFail"，同样落到包内快照；顶部状态条 + 「重试」给出原因。

3
读包内快照

cloud_snapshot.js 同步写入 window.BUSAN_CLOUD_SNAPSHOT，避免 file:// 下 fetch 被拒。

4
与联网同构回答

useSnapshot() 把快照塞进同一 db，compose() 产出同结构回答，只把徽章换成「离线 · 包内数据」。

5
附近与地图仍可用

快照带 8 条坐标：直线距离、NAVER 深链、Google 兜底都能算，断网不影响找路。

SHARED PIPELINE · 两条分支共用

手机端渲染层：问答 → 卡片 → 官网 → 追问

顶部状态三语按钮 + 状态点（绿=联网 / 橙=离线）+「重试」；状态点 pulse 表示正在取数。
两排 chip玩法 / 出行，首项「自动」；选中即成为唯一主数据源，换语言即时重译。
回答气泡标题 + 3–5 条要点 + 来源行；轻量 markdown（粗体 / 分隔线 / 列表）。
候选卡前 2 个带「推荐」徽章与公里数，四个按钮：导航 / 地点 / 网页地图 / Google；其余折叠进「其余 N 个（点开看）」。
定位兜底拒绝或超时 → 列 3 个已收录景点当起点，点一下即算距离，流程不中断。
APP SHELL · 壳与权限

MainActivity：三个 JS 接口，不填任何地址

  • 启动直接 loadUrl("file:///android_asset/index.html")；已删除 setup.html，不再要求「同 Wi-Fi + 电脑跑服务」。
  • netAllowed() 走 ConnectivityManager（SDK<23 退回 getActiveNetworkInfo()）。
  • fetchText(url,cbId) 线程池异步 GET，12 s / 15 s 超时，伪装 Android Chrome UA，回调 window.__busanHttpDone。
  • requestLocation() 运行时申请精/粗定位；授予后回调 __busanLocReady()；WebView 地理权限直接放行。
  • nmap:// 等 scheme 交系统 App，没装只提示一次，不阻断网页地图兜底。
DATA CONTRACT · 一份数据三处落地

cloud_build.py 生成，内容完全一致

  • mobile/cloud/spots.json — 随 GitHub 发布，App 联网直读（55.7 KB）。
  • android/assets/cloud_snapshot.json — 打进 APK，作为离线数据源。
  • android/assets/cloud_snapshot.js — 同一份 JSON 包成 window.BUSAN_CLOUD_SNAPSHOT，供 file:// 同步加载。
  • 结构：schema 2 + updated_at + 三语 strings + 8 个景点（中/韩/英字段、别名、坐标、官网 url/mId/host）。
  • 改数据只改 data.json 后重跑 python cloud_build.py，三份产物一起更新。

这一版刻意不做的事

不要求填电脑 IP、不依赖局域网服务、不在手机上跑 Python；不做登录（删 setup 页时一并移除）；不把「定位」当成营业/拥挤数据；距离只给直线，通勤时间交给地图 App。

如实标注的边界

① APK 内没有大模型成稿链路，联网回答是「云端库字段 + 官网上文摘要」的规则组装，官网正文用锚点启发式抽取；② 官网只覆盖已录入 mId 的景点，抓取失败会明说；③ 本轮验证在雷电模拟器完成，两名真人手机对比测试仍未做；④ 模拟器只能验「有网 / 云端库取不到」两种状态，飞行模式会切断 adb，纯「无网络权限」分支未截图。

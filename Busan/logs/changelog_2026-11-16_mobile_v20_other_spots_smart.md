### 1.2 任意景点都能从当前位置出路线

`cloud.js`：

- `routeTo()` 删除写死的“甘川文化村通常需要地铁 + 小巴”，改为按 `title` 生成“去 XX 的线路与班次以 NAVER 实时结果为准”。
- `answer()` 只要命中景点且问题含“怎么去/怎么走/路线/交通/当前位置/从我”，并且有实时坐标，就调用 `routeTo(s, pos)`，不再只认甘川或只认“从当前位置”。
- 每个目的地仍输出 3 类走法 + 3 个 `nmap://route/...` 深链。

实测：

```
从当前位置去海云台怎么走
→ 海云台海水浴场 · 直线约 13.5 km（±38 m）
→ 公交 / 打车约 36 分钟 / 步行约 193 分钟
→ 3 个 NAVER 深链
```

### 1.3 没有目的地：当前位置去其他景点

新增 `C.nearbyRoutes(pos)`：

- 按直线距离列最近 3 个收录景点；
- 每个点给出距离、类别和“从当前位置去 XX 怎么走”的选项；
- 点击后直接进入该点的实时路线。

实测（模拟 35.10,129.03）：

```
1. 南浦洞BIFF广场 — 0.2 km
2. 龙头山公园 — 0.3 km
3. 札嘎其市场 — 0.4 km
```

未授权时不再硬回“库里没有”，而是新增 `nearbyRoutePermissionCard`：

- 显示“路线 · 需要地图定位权限”；
- 点“允许定位并继续”后调用 `BusanLive.ensure`，授权后列最近 3 点；
- 拒绝/超时给出原因，并回退到 3 个推荐点。

### 1.4 智能问答

意图 JSON 从 4 类扩展到 6 类：

```
recommend | route | spot | general | nearby | unknown
```

`aiIntent` system prompt 新增：

- “附近/周边/走路能到”且无明确景点 → `nearby`；
- 天气、带娃、两天安排、下雨备选、预算、吃饭等开放建议 → `general`；
- 仍要求模型纠正错字、只输出一行 JSON。

`answerWithIntent` 新增：

- `nearby`：有坐标时 `C.nearbyAnswer`，否则回退推荐；
- `general`：3 个候选点 + 标签“智能回答 · 大模型”；
- `route` 无目的地：有坐标时 `C.nearbyRoutes`。

`C.recommend` 增加条件化兜底：

- “下雨/室内” → 札嘎其市场、西面、龙头山公园；
- “带孩子/亲子” → 松岛、海云台、甘川；
- “少走/老人/轮椅” → 海云台、松岛、札嘎其。

`finishAnswer` 对 `kind=general` 新增云端 2–3 句总结，system prompt 明确：

- 只能用候选点和参考内容；
- 不得编造门票、开放时间、价格、线路号或新地点；
- 如果候选不合适，要直说。

真实 Kilo 验证：

```
HTTP 200
{"intent":"general","spot":"","time":"","from_current":true}
```

对应问题“下雨天有什么室内备选”。

### 1.5 planner 分流补强

`planner.js` 的路线守卫从“必须有具体景点”扩展为：

- 有具体景点，或句子里有“当前位置/从我这里”；
- 且含“几条路/怎么去/路线可/交通方式”等；
- 且不含“规划/安排/行程/一日游/半天/怎么玩”等规划词；
- 则 `return false`，交给 `ask()` 的路线流程。

这样：

- “从当前位置去其他景点有几条路线” → 不再被 planner 抢走；
- “甘川文化村路线规划”“釜山两天怎么玩” → 仍进行程规划。

## 4. 已知限制

1. **新景点坐标是近似值**：用于直线距离和 NAVER 深链起终点，不替代 NAVER 的道路级路线；正式使用应以 NAVER 实时结果为准。
2. **新景点没有录入官网**：`official.url` 为空，因此不显示官网核对块，不编造开放时间/票价；问门票/开放时间会回退到概览。
3. **NAVER 路线仍未抓取**：没有 NAVER Directions API Key，当前只生成 `nmap://` 深链；App 摘要基于直线距离和三类走法，不包含具体线路号/班次。
4. **未真机验证**：`adb devices` 仍为空；系统权限弹窗、授权回传、`nmap://` 拉起 NAVER 需要真机确认。
5. **历史会话重放**：`rerenderAll()` 仍走旧的 `cloudAnswer()`，旧路线问题可能显示静态交通；新提问走 v2.0 流程。
6. **通用建议仍是“候选点 + 模型短评”**：没有接天气/营业状态实时 API；模型只做排序和解释，不替代事实查询。
